# ZooWork 品牌视觉使用规范

> [!abstract] 目标
> 让官网、ZooWork 工具以及未来 React Web 平台共用品牌基础，并在营销表达与工作界面中采用清楚、可复用的使用规则。设计师和开发者应能判断颜色、字体和资产在什么场景可以使用，而不只拿到一份素材清单。

本篇记录规范来源、已确认方向和待验证项目。品牌资源和交互示例已进入组件库预览；应用线上字体尚未迁移。使用方式见 README.md。

## 2. 颜色的使用范围

### 2.1 品牌色与操作色分别定义

“品牌色”表示品牌识别和强调；“主要操作色”表示操作优先级，两者不应绑定成同一个含义。官网当前主要按钮使用深墨紫，工具普通主要按钮使用中性深色，亮紫色只在特定位置出现。

以下官网色值已与当前部署 CSS 核对：

| 角色 | 官网当前色值 | 当前使用与建议规则 |
| --- | --- | --- |
| 品牌深色 Ink | `#0E0522` | Logo、Hero 标题、主要 CTA。作为深色品牌基调；与亮紫色强调区分 |
| 品牌强调 Violet | `#5755C6` | 角色关键词、部分行动链接、标签及演示关键节点。用于引导注意力 |
| 浅紫衬底 | `#E8E7F8` | 强调标签、演示气泡及局部交互背景；通常与深色文字或强调紫配对 |
| 官网次级文字 | `#4F4964` | 描述与次级信息的品牌灰紫色 |
| 官网弱化文字 | `#7D7895`、`#8F8BA8` | 当前存在的弱化文字颜色。作为现状记录，不直接保证任何字号、背景组合都可用 |
| 官网表面 | `#FFFFFF`、`#F7F7F7` | 页面与分区的主要底色，保持大面积中性背景 |
| 官网分隔 | `#E5E1EC` | 边框与分隔，形成轻层级 |

工具 Paper Focus 当前源码主要使用 `#34322D` 作为前景、主要操作、链接及焦点颜色，卡片为白色，侧栏和悬停使用浅灰。组件库基础 Tokens 另有 `#181818` 等中性色；这是基础层与主题层的现状差异，后续应以实际组件最终样式核对并收敛，不能把两套原始色值都交给使用者自由挑选。

### 2.2 官网与工具的使用矩阵

| 场景 | 官网规则 | 工具规则 |
| --- | --- | --- |
| 主标题、正文 | 主体使用深色；局部品牌关键词可强调紫 | 主体使用中性色；普通功能标题不通过紫色吸引注意 |
| 主要按钮 | 沿用深墨紫底、白字 | 普通创建、保存、发送、连接等沿用中性主要操作色 |
| 次级按钮 | 白底 / 透明底、细边框；局部浅紫交互反馈 | 中性边框与悬停，避免普遍增加紫色描边 |
| 行动链接 | 产品区等位置允许使用强调紫 | 工具常规链接沿用中性色与既有交互提示 |
| 导航、Tabs、表单选中 | 根据官网组件记录局部品牌反馈 | 一级、二级导航与 Tabs 维持中性选中样式；表单选中也不因品牌是紫色而整体改紫 |
| 键盘焦点 | 当前存在紫色焦点描边，保留可见焦点 | 普通控件沿用中性焦点体系；始终保证可辨识性 |
| New / Updated / 更新可用 | 可作为小范围提示 | 亮紫色的主要允许场景；可用浅紫底紫字、实紫底白字或小圆点，按组件统一变体 |
| 普通标签、分类、数量 | 中性为主，有明确品牌强调才使用紫色 | 默认中性；不能把所有 Badge、计数器和标签都做成紫色 |
| 成功、警告、错误、普通信息 | 使用各自语义颜色 | 同样使用独立语义颜色，不用紫色代替错误或警告 |
| 插图、产品演示、流程图 | 允许紫色节点、连线和局部底色，服务品牌叙事 | 仅在明确的品牌展示区域考虑；工作内容区维持中性表面 |

官网演示中出现的紫色选中导航、聊天气泡和模型标签，是营销画面的一部分，不自动成为工具组件的默认样式。

### 2.3 状态配色规则

当前 Connector 的错误状态使用红色标签与警告图标；等待状态使用橙色；可用连接状态使用绿色；停用或不可用使用灰色。规范沿用其语义分工。

- **成功 / 已连接**：绿色，仅表达操作结果或正常连接状态。
- **警告 / 等待处理**：黄橙色，结合状态文字。等待与风险可使用不同组件语义，但避免无规则新增相近颜色。
- **错误 / 危险操作**：红色；错误说明与删除类操作各自使用对应变体。
- **普通信息**：按现有信息组件使用蓝色，不与品牌紫混用。
- **未连接 / 停用 / 禁用**：中性色，结合文案、图标和交互限制，不只降低透明度。
- **更新可用**：品牌紫表示有新版本或更新，不表示失败；纯圆点也需具备可访问名称。

每个语义颜色应成套定义文字、背景、边框及交互状态。深色主题单独配套，不把浅紫底或浅色页面的颜色原样搬入暗色背景。

建议将普通文本的对比度目标设为至少 4.5:1，大文本至少 3:1，具体依照 [WCAG 2.2 文本对比度规则](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。当前灰色值仅是来源记录，需要结合真实背景、透明度和字号检查；“线上正在用”不等于已经通过可读性验收。

### 2.4 已发现的例外与待收敛项

| 现状 | 处理建议 |
| --- | --- |
| 官网强调紫 `#5755C6`，促销 Badge `#5754C6`，通用营销焦点 `#6D5CE7` 并存 | 促销色可优先对照统一；焦点先检验对比度与识别度，再决定是否共用色值。不能仅因色相接近就直接删除 |
| 工具 `AgentUpdateBadge`、更新按钮以及导航内的紧凑更新按钮均使用品牌紫 | Badge 符合用户确认方向。紫色更新按钮作为现有例外记录；不将它推广成通用紫色主要按钮 |
| 创建 Agent 弹窗存在紫绿模糊装饰 | 按用户确认纳入 Color 的创建氛围背景配方，限定在创建 / 欢迎标题背后，不推广到普通按钮、导航和表单底色 |
| `brand-ink` 在组件库实际指向亮紫，而官网 `zoowork-ink` 指向深墨紫 | 统一语义命名，清楚区分品牌深色与品牌强调色，避免根据名称误用 |
| 基础 Tokens 与 Paper Focus 的中性色、警告色存在多组值 | 按当前主题最终呈现建立一套明确映射，保留必要场景差异，不让业务自行选色 |

### 2.5 产品渐变配方

2026-10-13 根据用户提供的线上 Agents 截图及对应源码，纳入两种独立用途的渐变。预览位置为 Color / 氛围背景与活动曲线，不包含整页业务界面。

| 配方 | 源码参数 | 使用规则 |
| --- | --- | --- |
| 创建氛围背景 | 左层 `--brand-ink`（`#5755C6`）12%；右层 `--ecap-success-border` 35%（Paper Focus 浅色 `#B9DEC5`，深色 `#3E674B`）；两层各宽 60%、高 160px、向上偏移 64px、外侧偏移 32px、模糊 40px；容器高 160px，顶部圆角继承且裁切 | 两层模糊椭圆叠加，局部营造创建 / 欢迎氛围；底色与文字仍跟随主题。绿色源自现有主题变量，不代表成功状态 |
| 活动曲线 | `#7874D7` 0% → `#56B3AB` 50% → `#6BDC69` 100%；从左到右；1.5px 线宽；源码明暗主题使用相同色标 | 表达一条连续数据序列，颜色对应横向位置，不表示进度、成功程度或不同类别；数量仍由线高及数据文案表达 |

创建背景导出 `zw-creation-aura` 与 `--zw-creation-aura-*`；曲线导出 `--zw-activity-*` 和 `--zw-gradient-activity`。均在可选的 `brand.css` 中。SVG 必须为每个实例生成唯一渐变 ID，并保留 `userSpaceOnUse`，避免零活动水平线没有包围盒高度而丢失渐变。Color 示例提供“有活动 / 无活动”切换。

来源为 `agents/components/CreateAgentDialog.tsx`、`AgentActivityChart.tsx`、`AgentActivityChart.module.css`，主题颜色来自 `zoowork-theme.css`。源码提取已核对，截图验收尚受浏览器连接限制；不宣称已逐像素验证线上。此次建立配方不改变线上业务逻辑。

## 3. 字体的场景角色

### 3.1 两种风格，中英文各有对应字体

| 角色 | 英文 | 中文 | 场景 |
| --- | --- | --- | --- |
| 品牌展示 Display | **GFS Didot**，已确认 | **Noto Serif SC**，当前推荐 | 官网 Hero、品牌表达型大标题、工具欢迎语等 |
| 正文与功能 UI / Body | **Inter**，已确认 | **Noto Sans SC**，已确认 | 正文、普通页面标题、导航、按钮、表单、卡片、表格、提示、弹窗、Badge |

“两种风格”指展示衬线与界面无衬线，不要求把中英文硬塞进两个字体文件。GFS Didot 不提供中文字形，中文展示使用宋体配对，不能退回无衬线。

### 3.2 中文展示推荐：Noto Serif SC

推荐理由是其宋体笔画粗细对比、衬线与稳重的阅读气质，可以和 GFS Didot 形成协调的中英文展示组合。这是设计搭配判断，不表示它是 Didot 的中文版本，也不表示已经完成像素级实样验证。

Noto Serif CJK 与 Adobe 思源宋体来自同一合作项目体系；Google Fonts 的 **Noto Serif SC** 是明确支持简体中文的衬线字体。工程中已有 `Noto_Serif_SC` 的字体加载配置，可在统一规则时复用并核查实际字形加载。

- [Google Fonts 官方字体说明](https://github.com/google/fonts/blob/main/ofl/notoserifsc/DESCRIPTION.en_us.html)：简体中文衬线设计，支持多个字重。
- [官方元数据](https://github.com/google/fonts/blob/main/ofl/notoserifsc/METADATA.pb)：衬线分类、简体中文支持、字重轴与源码来源。
- [官方 OFL 1.1 许可](https://github.com/google/fonts/blob/main/ofl/notoserifsc/OFL.txt)：允许商业项目使用和网页嵌入；分发字体时保留版权及许可，不单独出售字体；修改再发布时按许可处理命名等要求。使用字体生成的页面和设计稿不因此要求开源。
- [Adobe 项目背景](https://ccjktype.fonts.adobe.com/2017/04/source-han-serif-history-development.html)：说明 Source Han Serif / Noto Serif CJK 的合作关系。

### 3.3 排版规则

1. **按用途选字体。** 展示标题表达品牌，功能文字负责阅读和操作。普通设置页标题即使字号较大，也使用无衬线。
2. **英文展示沿用 GFS Didot Regular。** 不通过浏览器合成粗体或斜体制造新风格；优先用尺寸、留白与布局建立强调。
3. **中文展示先以 Noto Serif SC 400 对照。** 如实际显示偏细，再比较 500。具体字重与行高是待实样确定的建议，尚未固化成生产 Token。
4. **中英文分别定义排版参数。** 英文 Didot 的负字距与紧行高不能直接套给中文；混排需检查数字、英文、中文标点和基线。
5. **无衬线统一 Inter / Noto Sans SC。** 后续迁移覆盖正文、导航、控件和局部字体覆盖，不只修改 body。
6. **字号按场景变化。** 官网展示需要较大字号和留白；工具标题和控件需要适合连续工作的密度，字体家族保持统一即可。
7. **字体加载作为组件库接入要求。** 记录文件版本、加载方式与备用字体，避免设计稿安装了字体而消费项目静默回退。
8. **Logo 字标按资产复用。** 现有 Jost 字标不属于页面文字，不因 UI 统一 Inter 而重排或换字。

官网英文 Hero 当前使用响应式 `clamp()`，主要区间为 48–72px、小屏为 36–48px，行高 1.08、字距 -0.018em。用户截图的 53.62px 是特定视口下的计算结果，不是固定字号。中文 Hero 当前源码仍有无衬线分支，因此中文展示宋体属于待落实的统一方案。

### 3.4 当前需要迁移的字体

工具 Paper Focus 中的 Libre Baskerville、DM Sans，Onboarding 的 Cormorant Garamond，导航系统字体覆盖，官网局部 Roboto，以及组件库默认 Source Serif 4，都需按其实际用途映射到上述两类角色。

Figma 演示内容中出现的 Figtree、Cousine 等不自动加入品牌正式字体表。代码或终端内容的专用等宽字体单独按内容规则管理，不作为额外品牌展示字体，也不在本次讨论中直接删除。

## 4. 正式资产的使用规则

### 4.1 Logo 资产及适用场景

官网与工具当前深色横版 Logo 均为同一图形和字标。本轮比对两份 PNG 的尺寸及 SHA-256，内容完全相同，都是 1446 × 390；只是存放路径不同。没有发现需要重新选择的两套正式标识。

| 资产 | 当前依据 | 建议使用规则 |
| --- | --- | --- |
| 深色横版 Logo | 官网 Header 和工具展开导航都在使用 | 白色、浅灰等浅背景优先使用；保持原始比例和字标组合 |
| 白色横版 Logo | 工具导航源码提供独立白色资产 | 深色背景使用；优先选用正式白色文件，避免各页面自行滤镜调色 |
| 独立标志图形 | 工具折叠导航及官网素材目录存在图标资产 | 空间有限、品牌已可识别时使用，例如折叠导航；不把横版字标压缩进正方形 |
| Favicon | 官网提供专用 64 × 64 文件 | 用于浏览器标签等小尺寸场景，按专门的导出规格管理 |
| 竖版 / 其他组合 | Figma 中存在对应排版变体 | 适合受限版面或品牌物料；尚不能因此设为网站导航的默认版式 |

官网当前 Header Logo 桌面渲染宽度 144px，窄屏 104px，更窄时 80px；工具展开导航图片高度 32px、折叠图标容器为 24px。这些是当前组件尺寸，不是已定义的品牌最小尺寸，且图像包含透明留白，不能直接以文件边界等同可见图形边界。

### 4.2 Logo 使用规则

- 使用正式文件及正确明暗版本；保持标志、字标、相互间距和比例。
- 不重新输入 ZOOWORK 文字来模拟字标，不拉伸、重描、随意加阴影或改成强调紫。
- 保留足够净空，避免与按钮、边框和文字挤压；具体净空比例和最小可读尺寸仍需基于源文件实测后定义，不在本篇臆造数值。
- 有导航功能的 Logo 提供可访问名称与明确跳转；折叠按钮保持独立交互和键盘焦点。
- 同一资产使用统一注册入口或导出包，官网、工具和预览按用途引用；不同项目不再自行复制并改名生成多个来源。

### 4.3 其他视觉资产

| 资产类型 | 当前使用 | 纳入规范的方式 |
| --- | --- | --- |
| 品牌氛围背景 | 官网 Hero 使用低饱和、柔和、具有绘画肌理的背景，承托清晰的产品画面 | 归入 Brand / Imagery。可用于官网和明确的品牌展示区域；工具常规卡片、表格、表单仍使用中性清晰背景 |
| 产品截图 / 演示 | 官网展示工具工作区和交互场景 | 记录对应版本与更新时间；静态宣传图与真实可交互组件分别管理。不能把完整截图当成组件交付 |
| Agent 头像 | 官网与工具都有具象角色或 Agent 身份图 | 作为可替换内容资产；统一裁切、容器和加载失败表现，不让每张头像改变组件骨架 |
| 第三方 Connector / 模型 Logo | 线上 Connector 保留 Gmail、GitHub 等原有识别色 | 保留品牌原色和比例，不统一染成 ZooWork 紫；统一的是图标容器、视觉尺寸和对齐 |
| 功能图标 | 工具以线性操作图标为主，源码中存在共享图标及 Heroicons | 通过共享图标入口定义尺寸、笔画与对齐；功能图标与第三方品牌图标分开管理 |
| 行业案例图、认证图等 | 官网内容区已有对应素材 | 标明来源、用途与内容版本，不自动作为所有平台默认可复用的品牌资产 |

建议资产目录至少记录：稳定名称、用途、源文件/Figma 节点、导出格式、明暗版本、比例与裁切要求、适用背景、可访问文案、来源/许可、维护人和版本状态。现有 PNG 可先登记；SVG 应由可靠矢量源导出，不能把低清 PNG 描摹后当成正式源文件。

## 5. 放入 Design System 的位置

| 位置 | 需要呈现的内容 |
| --- | --- |

## 6. 需要继续定义与验证的项目

1. Noto Serif SC 与 GFS Didot 的中英文实样配对：中文 400 / 500、行高、字距、标点与移动端可读性。
2. 工具紫色更新按钮的明确例外范围；创建氛围背景已按限定场景保留为独立配方，不作为普通控件默认皮肤。
3. 官网相近紫色值、工具中性色和语义色的统一映射；浅色与深色状态配对。
4. 字体资源和正式 Logo 的统一引用方式；重复资产的单一维护源。
5. Logo 的净空、最小尺寸、深浅底及繁杂背景可用性；Figma 的旧说明与色板标签修订。
6. 真实线上页面的交互状态与最终计算样式复核；浏览器恢复后补充，当前不标记为验收通过。

## 8. 图标、插画与更新标记

- 功能图标分为 Heroicons 与产品自有 SVG。导航动画保留原几何；发送、头像编辑、面板开关等使用源码路径，不能用“看起来差不多”的 glyph 替换。
- 第三方服务 Logo 保留原颜色和比例；功能图标继承 currentColor，按所在控件的语义着色。
- 空状态使用 StateIllustration 的原 4:3 素材、裁切和主题适配。头像、空状态插画、官网氛围图分别登记，不能混用。
- 产品更新圆标为 16px，网站促销胶囊为 14px 高、8px 文字；它们用途和尺寸不同，但在比较展示时文字保持同一基线。促销文案是活动数据，不应固化成永久产品徽标。
- 图标与插画目录覆盖源码引用的本地资源；实时集成服务 Logo 和用户上传素材需由业务资产系统管理。

## 9. 聊天提及

显式选中的 `@Agent` / `@同事` 使用品牌紫文字与浅紫胶囊背景，表示消息中的对象引用。输入区与发送后的消息使用同一种表现。普通输入文字与候选菜单保持中性；粘贴的普通 @文本不会自动建立对象身份。
